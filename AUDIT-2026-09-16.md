### P1-1. Боевой цикл Гильдбосса недостижим (мёртвый код), и он же глушит `duelTick`

`src/game/logic.ts`, функция `tick()`:

```
2598  if (st.guildBoss && st.guildBoss.active && !st.guildBoss.claimed) {
2606    if (now >= updatedGuildBoss.expiresAt && ...) updatedGuildBoss.rewardPending = true;
2615    return { ...st, guildBoss: updatedGuildBoss };        // ← ВЫХОД ЗДЕСЬ
2616  }
2618  // Обновление таймера … — боевой цикл
2619  if (st.guildBoss && st.guildBoss.active && !st.guildBoss.claimed) {   // ← никогда не выполнится
...
2667    st.guildBoss = updated;                                            // + мутация состояния
```

Условия блоков идентичны, а первый делает `return` — значит, второй блок (строки 2618–2668:
автоатаки героя, ответные удары босса, лидерборд) **никогда не исполняется**.

Следствия:
- босс теряет HP только по ручному нажатию (`GUILD_BOSS_ATTACK`), «боя на автопилоте» нет;
- `gb.heroHp` не падает, `bossAttackT`/`playerAttackT` не тикают — индикаторы боя мертвы;

- строка 2667 к тому же мутирует `st` (см. P1-2).

Что делать: объединить оба блока в один (`if (gb.active) { …таймер…; if (gb.isFighting) { …бой… } }`),
не прерывать `tick` через `return`, возвращать `{ ...st, guildBoss: updated }` в конце.
Обязательно покрыть тестом (`GUILD_BOSS_START` → 20 × `TICK` → `hp` и `heroHp` уменьшились):
сейчас `GUILD_BOSS_START`/`GUILD_BOSS_ATTACK` в тестах отсутствуют вовсе.

### P1-2. Редьюсер нарушает иммутабельность (мутации общего состояния)

| Место | Код |
|---|---|
| `logic.ts:2185` | `existingEntry.damage += damage;` — мутирует объект внутри `leaderboard` предыдущего стейта |
| `logic.ts:2646` | то же в мёртвом блоке |
| `logic.ts:2667` | `st.guildBoss = updated;` |
| `logic.ts:2856-2972` | `migrateState` мутирует переданный объект целиком (`s.hero.gold = …`, `s.battle = …`) |

Чем опасно: `useReducer` ожидает чистую функцию; при повторном вызове (StrictMode, двойной рендер)
возможно двойное начисление урона, а «старый» стейт незаметно меняется — сравнение по ссылке
перестаёт быть надёжным для мемоизации в `useGame`.

Минимальный фикс:

```ts
const leaderboard = (gb.leaderboard || []).map(e =>
  e.name === playerName ? { ...e, damage: e.damage + damage } : e
);
if (!leaderboard.some(e => e.name === playerName)) {
  leaderboard.push({ name: playerName, damage, losses: 0 });
}
```

`migrateState` лучше возвращать новый объект (`return { ...s, … }`), тогда его можно звать без
побочных эффектов и для локального, и для облачного сейва.

## 3. Средний приоритет (P2) — надёжность, DX, производительность

### P2-1. Нет ErrorBoundary и глобального перехвата ошибок

В `src/` нет ни `componentDidCatch`, ни `window.onerror`/`unhandledrejection` (проверено grep).
Любая ошибка рендера (как P0-1/P0-2) даёт полностью белый экран без кнопки «перезагрузить» и без
телеметрии. Добавить:

```tsx
class ErrorBoundary extends React.Component<{children: React.ReactNode}, {err: Error | null}> {
  state = { err: null };
  static getDerivedStateFromError(err: Error) { return { err }; }
  componentDidCatch(err: Error, info: React.ErrorInfo) {
    navigator.sendBeacon?.("/api/client-error", JSON.stringify({ msg: err.message, stack: String(info.componentStack).slice(0, 2000) }));
  }
  render() { return this.state.err
    ? <FallbackScreen err={this.state.err} onReset={() => location.reload()} />
    : this.props.children; }
}
```

Плюс серверный `POST /api/client-error` (сейчас такого эндпоинта нет) — иначе о падениях у игроков
не узнать.

### P2-2. CI не проверяет типы и тесты

## 4. Низкий приоритет (P3) и идеи по улучшению

1. **`isProgressSafe` содержит нерабочую проверку**: `state-simulator.ts:218` читает `prevHero.zones`, но `zones` лежит в корне стейта, а не в `hero` → правило «не более +2 зон за тик» не действует.
2. **`structuredClone` + 50 тиков на каждый `/api/settle`** блокируют event loop — при возврате эндпоинта в работу ограничить частоту и/или вынести симуляцию в worker.
3. **Разбить `logic.ts` (2999 строк)** на модули `battle.ts`, `run.ts`, `guild.ts`, `duel.ts`, `economy.ts` с единым реэкспортом; пустые `src/game/battle`, `src/game/combat` уже заготовлены под это.
4. **`tick` не останавливает волну при модалке дара** — если выбор дара доделают, игрок будет получать урон во время выбора.
5. **`main.tsx` без `StrictMode`** — после исправления P1-2 включить, чтобы такие баги ловились автоматически.
6. **Логи сервера**: `console.log` на каждый settle/corrections; перевести на структурированный логгер (pino) с уровнями и без чувствительных данных.
7. **Идемпотентность наград**: у `/api/rewards/claim` есть `event_id` (хорошо), у `/api/activity/claim` и гильд/дуэль-наград такой защиты нет — при ретрае клиента возможны двойные начисления (сейчас частично спасает транзакция + `lastClaimDate`).
8. **Окно входа 24 ч**: `verifyLaunchParams` (`index.ts:370`) принимает подпись, действительную сутки, а `x-vk-launch-params` переиспользуется во всех запросах — сократить до ~1 ч и добавить nonce/сессионный токен.
9. **Парсинг `.env` вручную** (`index.ts:10-16`): не срезает кавычки, не понимает `export`, не игнорирует `#`-хвосты — использовать `dotenv` или `node --env-file`.
10. **Мелочи UI**: пустой pet-экран показывает «Загрузка…» вместо приглашения получить питомца; `GuildBossScreen` не следит за `attacksLeft` (уходит в минус); неиспользуемое поле `pet.canLevelUp`.
