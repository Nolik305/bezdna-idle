# Аудит и план развития

Дата аудита: 2026-09-13

## Что исправлено в текущем пакете

- Экран «Скилы» больше не падает: у пассивок добавлены функции `desc`.
- Стоимость активных скиллов смягчена с `2.15^level` до `1.32^level`.
  - Цена 40-го уровня теперь меньше 10 млн золота, а не сотни триллионов.
- Поздний XP масштабируется по глубине зоны через множитель `1.018^(zone * 12 + wave - 1)`.
- `Stats.dmgPct` теперь возвращает рассчитанное значение, а не всегда `0`.
- Добавлены четыре пассивки мага и четыре пассивки лучницы.
- UI показывает классовые пассивки только соответствующему классу.
- Reducer запрещает прокачивать пассивку другого класса.
- Бонус урона скиллов теперь учитывается и в DoT.
- Сейвы VK больше не записываются в общий localStorage; VK-режим использует облако.
- Сервер принимает большие значения накопительных счётчиков (`goldEarned`, `kills`, `items`, `dmgDealt`, `shards`).

Проверки после изменений: production build успешен, 127 тестов проходят.

## Главная модель прогресса

У героя есть три независимых слоя:

1. Уровень и XP: дают очки пассивных навыков.
2. Активные скиллы: покупаются за золото и автоматически применяются в бою.
3. Экипировка/мета-системы: дают характеристики и должны поддерживать рост врагов.

Раньше активные скиллы имели недостижимую экспоненциальную цену, а пассивки заканчивались на 10 ранге. Из-за этого герой мог быть высокого уровня, но фактически не иметь доступных улучшений.

## Баланс: целевые правила

- Каждый новый уровень должен давать ощутимый выбор: пассивка или накопление на активный скилл.
- Цена скилла 20-го уровня должна измеряться десятками/сотнями тысяч золота.
- Цена скилла 40-го уровня должна измеряться единицами миллионов.
- Поздняя зона должна давать больше XP, чем ранняя, не только более толстых врагов.
- Стартовый DPS классов должен отличаться не более чем на 3-5%.
- Маг получает burst и cooldown-бонусы.
- Лучница получает crit, скорость атаки и DoT.
- Общие пассивки остаются общими, но классовые пассивки дают различный стиль игры.

## Аудит механик

### Активные скиллы

Статус: работают как авто-каст.

- `SKILLS` описаны в `src/game/data.ts`.
- `farmTick`, roguelike и duel используют reducer-логику авто-каста.
- UI не даёт ручной кнопки, поэтому название «активные» означает «автоматически применяемые способности».
- Прямой урон и DoT теперь учитывают `extraSkillDamagePct`.

Следующий шаг: добавить ручной каст-кнопки в Battle/Run/Duel только если нужен игровой контроль. Иначе переименовать раздел в «Боевые способности».

### Пассивные навыки

Статус: общий набор плюс классовые ветки.

Общие пассивки: живучесть, каменная кожа, жадность, удача, мудрость, скрытая казна и базовые универсальные бонусы.

Маг: арканная мощь, фокус заклинаний, всплеск маны, арканный барьер.

Лучница: меткая стрельба, шквал стрел, ядовитые наконечники, охотничий инстинкт.

При добавлении новых пассивок обязательно обновлять одновременно:

- описание в `PASSIVES`;
- обработку в `getStats`;
- фильтр класса в `SkillsScreen`;
- тест на фактическое изменение характеристики.

### XP и золото

Статус: базовый поздний баланс исправлен.

Проверять при каждом изменении баланса:

- `xpNeed` и XP врагов;
- `enemyHpPow` и `enemyDmgPow`;
- золото обычного врага и босса;
- стоимость скилла;
- бонусы золота/XP от пассивок, VIP, предметов и событий.

Важно: серверный `state-simulator.ts` должен использовать ту же модель offline-дохода, что и клиент. Расхождение формул клиента и сервера может откатывать прогресс или давать неожиданный доход.

### События

Статус: базовые события реализованы и покрыты тестами.

Проверены: жаба, сундук, бард и гоблин; сезонные очки и награды.

Риски:

- событие может потеряться, если в этот момент уже открыта другая модалка;
- сезонный прогресс зависит от календарного текущего события;
- сезонные награды нужно сравнивать с поздней экономикой.

Следующий шаг: добавить очередь `pendingEvent`, чтобы событие не терялось из-за level-up/offline/activity modal.

### Боевой пропуск

Статус: UI и claim-actions есть, но нужно проверить начисление XP боевого пропуска. В текущей логике миссии и XP должны получать обновления от убийств, боссов, крафта и событий.

План проверки:

- убийство увеличивает миссию kills;
- каст увеличивает миссию casts;
- награда tier выдаётся один раз;
- premium не позволяет забрать недоступную ветку;
- смена сезона очищает старые награды.

### Питомцы

Статус: UI и экипировка есть, но бонусы питомцев нужно подключить к `getStats`.

Нужно проверить:

- бесплатный питомец доступен на нужном уровне;
- `equipped` и legacy `petId` синхронизированы;
- passiveBonus питомца меняет реальные статы;
- XP и уровень питомца не исчезают после cloud hydrate.

### Руны

Статус: есть state и reducer-actions, но UI вставки рун был неполным.

Нужно проверить:

- UI вызывает `RUNE_INSERT`;
- UI и reducer используют одну форму `RuneSlot`;
- бонусы рун входят в `getStats`;
- удаление руны возвращает корректное состояние.

### Бестиарий

Статус: экран открывается, но список частично mock.

Нужно подключить discovery к `killEnemy`:

- создать запись при первом убийстве;
- увеличить kills;
- выставить discovered/canClaim;
- обновить maxKills;
- дать награду один раз.

### Престиж

Статус: экран и actions есть; исправлен runtime-порядок чтения `prestige`.

Нужно проверить, что купленные бонусы действительно прибавляются в `getStats`, а не только отображаются в UI.

### База и турнир

Статус: state/reducer/UI есть, но нужны явные условия unlock и сезонный reset.

Нужно определить продуктовые правила:

- с какого уровня/зоны открывается база;
- когда активируется турнир;
- как обновляется leaderboard;
- какие награды доступны в конце сезона.

## Сервер и сохранения

- API запускается через `cd server && npm start`.
- PM2 запускается через `pm2 start npm --name game-api --cwd /var/www/game-project/server -- start`.
- `shared/src/game/*.ts` должны быть относительными symlink-ами, не путями `/home/...`.
- VK-сейв хранится в `players.state->'game'`.
- `server/.env` никогда не коммитится.
- При `HTTP 400: invalid_game_state` сначала смотрите поле в скобках.
- При `502 Bad Gateway` сначала проверяйте `curl http://127.0.0.1:3001/health`, потом PM2 и nginx.
